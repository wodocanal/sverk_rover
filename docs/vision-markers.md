# Камера: YOLO11n, ArUco и QR

## Модель

Вместо пользовательской `best.pt` теперь используется официальная **YOLO11n
COCO**. Старые веса и манифест удалены из исходников, новые включены в пакет
`rover_vision`. Модель знает 80 классов обычных объектов, но не сохраняет
специфические классы прежней дообученной модели.

Для CPU выбран вход 320×320 вместо 640×640. Это уменьшает вычислительную
нагрузку, но может снизить качество обнаружения мелких объектов. Лимит FPS
в настройках не гарантирует такую частоту: производительность на физическом
Raspberry Pi нужно измерять отдельно.

Источник, SHA-256 весов и информация о лицензировании приведены в
`src/system/rover_vision/models/README.md`. Веса Ultralytics имеют отдельные
условия AGPL-3.0 / Enterprise; лицензия кода пакета не заменяет лицензию весов.

## Использование в вебе

1. Откройте **Периферия → Камера → Обработка видеопотока**.
2. Если обработка запущена, нажмите **Выключить обработку**.
3. Выберите модель `YOLO11 Nano COCO`.
4. При необходимости включите **Распознавать ArUco (OpenCV)** и/или
   **Распознавать QR (OpenCV)**.
5. Для ArUco выберите словарь напечатанных маркеров, по умолчанию `DICT_4X4_50`.
6. Нажмите **Применить**, затем **Включить обработку**.
7. Нажмите **Показать обработанный поток**, чтобы увидеть рамки.

В списке детекций появятся классы объектов, ID ArUco и текст QR. QR-ссылки
не открываются автоматически. Если контур QR найден, но прочитать содержимое
не удалось, отображается «Не расшифрован». У маркеров нет фиктивного процента
уверенности нейросети.

Обе галочки по умолчанию выключены. Они управляют отдельными алгоритмами OpenCV,
но работают внутри общего конвейера: основная кнопка включает/выключает YOLO
и выбранные распознаватели вместе. Отдельного режима «только маркеры без YOLO»
в этом изменении нет. Параметры заблокированы во время обработки.

## ROS и сохранение

Результаты публикуются в `/detections` (`std_msgs/String`, JSON). Поле `kind`
отличает `object`, `aruco`, `qr`; общее количество находится в `count`, отдельно
добавлены `object_count` и `marker_count`. Маркеры содержат `corners` и `bbox`,
ArUco — `marker_id`/`dictionary`, QR — `data`/`decoded`.

Размеченное видео публикуется в `/image_processed` и
`/image_processed/compressed`. Обработка выполняется и без открытого веба,
если конвейер включён и поступают кадры камеры.

Изменения из веба являются текущими ROS-параметрами, как и остальные настройки
этой ноды. Для значений после перезапуска измените
`src/system/rover_vision/config/vision.yaml`: `model_name`, `detect_aruco`,
`detect_qr`, `aruco_dictionary`.

## Обновление ровера

Обновите и пересоберите `rover_vision` и `rover_web`. Если раньше использовалась
`best`, уберите соответствующее переопределение из своей команды запуска.
Colcon не всегда удаляет исчезнувшие файлы из старого `install`, поэтому при
обновлении проверьте и удалите **только старые артефакты этой модели**:

```bash
# Из корня workspace, при остановленной обработке камеры.
rm -f build/rover_vision/models/best.pt build/rover_vision/models/best.yaml
rm -f install/rover_vision/share/rover_vision/models/best.pt
rm -f install/rover_vision/share/rover_vision/models/best.yaml
# Для workspace, собранного с --merge-install:
rm -f install/share/rover_vision/models/best.pt install/share/rover_vision/models/best.yaml
colcon build --packages-select rover_vision rover_web
source install/setup.bash
```

Используйте тот же режим install, что и при первоначальной сборке workspace.
Пример выше для обычного install; добавляйте --symlink-install только если
он уже использовался. [Общая процедура обновления](operations.md).
После первой установки изменений перезапустите сервисы, запускающие vision
и web. Далее управляйте обработкой через страницу камеры.

В Python-окружении ROS нужны зависимости из `rover_vision/requirements.txt`
и OpenCV с `cv2.aruco` и `cv2.QRCodeDetector`. Проверяйте именно окружение сервиса,
а не только Python в интерактивном терминале. Проверено с OpenCV 4.6 и 4.11;
реальная YOLO-инференция — с Ultralytics 8.3.200 и CPU PyTorch 2.5.1 в ARM64
Docker. Не устанавливайте несколько pip-вариантов OpenCV одновременно.

Это распознавание в координатах изображения, не определение расстояния или
положения маркера в пространстве. Для последнего нужна калибровка камеры.
